01
Admin-2 Spatial Join
Merging raster & point data onto district-level polygons using sf + exactextractr
▼

Input

Admin-2 shapefile (GADM/geoBoundaries), raster predictors (NDVI, livestock density), point-level outbreak records with lat/lon

Output

Single sf data frame: one row per Admin-2 polygon with spatially summarised predictor columns appended

Why Admin-2?

District level aligns with WAHIS/OIE reporting granularity and provides enough within-country variation for random effects

The core workflow couples polygon-based extraction (rasters → Admin-2 zonal statistics) with spatial point-in-polygon join (outbreak points → district). All layers must share a common CRS before any join operation.

CRS Alignment

All datasets are projected to WGS84 (EPSG:4326) for global coverage. Where area-weighted operations are needed (e.g., total livestock count), an equal-area projection (e.g., ESRI:54009 Mollweide) is used before extraction, then the result is stored in the WGS84 master table.

library(sf)
library(exactextractr)
library(terra)
library(dplyr)

# Load Admin-2 boundaries
adm2 <- st_read("data/gadm_adm2.gpkg") |>
  st_transform(4326)           # ensure WGS84

# Load raster predictors
ndvi_r   <- rast("data/modis_ndvi_annual.tif")
lstk_r   <- rast("data/glw_cattle_density.tif")

# Align raster CRS to match polygons
ndvi_r  <- project(ndvi_r,  "EPSG:4326")
lstk_r  <- project(lstk_r,  "EPSG:4326")

# Zonal statistics: mean NDVI, sum livestock count, max elevation
ndvi_stats <- exact_extract(ndvi_r, adm2,
                fun = c("mean", "stdev"),
                append_cols = "GID_2")

lstk_stats <- exact_extract(lstk_r, adm2,
                fun = "sum",
                append_cols = "GID_2")

# Merge back to polygon table
adm2 <- adm2 |>
  left_join(ndvi_stats, by = "GID_2") |>
  left_join(lstk_stats, by = "GID_2") |>
  rename(ndvi_mean = mean, ndvi_sd = stdev,
         livestock_sum = sum)

02
Temporal Alignment
Matching annual predictor tiles to outbreak year, lagged variables, and multi-year outbreak handling
▼

Input

Spatially-joined Admin-2 table; MODIS annual composites (yearly GeoTIFF stack); GLW livestock layers (2005, 2010, 2015); vaccination coverage time series

Output

Panel dataset where each row's predictor values correspond to the correct calendar year (or lagged year) matching the outbreak start date

Why temporal matching?

Using the wrong year introduces information leakage (future predictors) or staleness bias; lagging vaccination by 1 year reflects immunological build-up delay

Predictors vary in temporal resolution. MODIS NDVI is available annually; GLW livestock density is released in ~5-year epochs; vaccination coverage comes from country-year records. The strategy below assigns each outbreak row the predictor value from the appropriate year.

MODIS Annual Tile Matching

# MODIS stack: layer names encode year (e.g., "ndvi_2005", "ndvi_2006", ...)
modis_stack <- rast("data/modis_ndvi_2000_2022.tif")

# For each outbreak, extract NDVI from the layer matching outbreak_year
extract_year_matched <- function(sf_obj, rast_stack, year_col) {
  years <- unique(sf_obj[[year_col]])
  results <- lapply(years, function(yr) {
    lyr_name <- paste0("ndvi_", yr)
    if (!lyr_name %in% names(rast_stack)) return(NULL)
    sub <- sf_obj[sf_obj[[year_col]] == yr, ]
    vals <- exact_extract(rast_stack[[lyr_name]], sub, fun = "mean",
                          append_cols = "GID_2")
    vals$year <- yr
    vals
  })
  bind_rows(Filter(Negate(is.null), results))
}

ndvi_yr <- extract_year_matched(adm2_outbreak, modis_stack, "outbreak_year")

■ Phase 2 — Outcome Construction
03
Binary Persistence Outcome
Defining outbreak persistence (duration > 28 days) and encoding as a binary response variable
▼

Input

Outbreak records with start_date and end_date fields from WAHIS/EMPRES-i; audit log of date-imputation decisions

Output

Binary column persist (0/1) appended to each outbreak row; class-balance summary; excluded row audit table

Why 28 days?

Threshold = maximum incubation period (~14 days for most TADs) + expected reporting lag (~14 days), ensuring reported duration reflects true biological persistence

Threshold Justification

The 28-day threshold is grounded in two independent delays:

  • Incubation period: FMD 2–14 days; HPAI 1–7 days; ASFV 4–19 days. Using the upper-bound maximum (14 days) covers all major TAD pathogens.
  • Reporting lag: WAHIS notification requirement is 24 hours for "immediate" events, but field confirmation + national reporting averages ~7–14 days. An additional 14-day buffer is conservative.
  • Epidemiological meaning: Outbreaks lasting longer than 28 days imply the pathogen has circulated beyond the index herd/location, indicating local amplification rather than a single-point introduction.
Persistence Definition
\[ \text{persist}_i = \mathbf{1}\!\left[\,d_i > 28\,\right], \quad d_i = \text{end\_date}_i - \text{start\_date}_i \text{ (days)} \] 
library(dplyr)
library(lubridate)

outbreaks <- outbreaks |>
  mutate(
    start_date = ymd(start_date),
    end_date   = ymd(end_date),
    duration   = as.integer(end_date - start_date),  # days
    persist    = as.integer(duration > 28)
  )

outbreaks <- outbreaks |>
  mutate(
    end_date_flag = case_when(
      !is.na(end_date) & end_date >= start_date ~ "valid",
      !is.na(end_date) & end_date <  start_date ~ "data_error",
      is.na(end_date) & (last_report_date - start_date) >= 28 ~ "imputed_report",
      is.na(end_date)                             ~ "excluded_persist",
      TRUE ~ "unknown"
    ),
    end_date = case_when(
      end_date_flag == "imputed_report" ~ last_report_date,
      TRUE ~ end_date
    ),
    duration = as.integer(end_date - start_date),
    persist  = if_else(end_date_flag %in% c("data_error","excluded_persist"),
                       NA_integer_,
                       as.integer(duration > 28))
  )

Class Imbalance Assessment

Logistic GLMM performance can degrade severely when one class dominates. If prop(persist=1) < 0.15 or > 0.85, the following mitigations are considered:

Imbalanced (<15% minority) Use weighted logistic regression (weights argument in glmer) or report sensitivity/specificity alongside AUC. Avoid accuracy as sole metric.
Acceptable balance (15–85%) Standard GLMM is appropriate. Report both classes in confusion matrix at the threshold that maximises Youden's J index.
04
Time-to-Reemergence (TTE) Variable
Computing inter-outbreak intervals, left-truncation, and right-censoring for Cox frailty models
▼

Input

Ordered outbreak records per Admin-2 × disease combination; study start date (t₀) and study end date (t_end) for censoring

Output

TTE dataset with columns: admin2_id, disease, t_start, t_stop, event (1=reemergence, 0=censored)

Why inter-event gap?

Reemergence is defined as a new confirmed outbreak in the same Admin-2 after the previous outbreak officially closed — requires chronological ordering within unit

The Cox frailty model requires a counting process (start, stop] format. For each Admin-2 × disease pair, we construct one row per inter-outbreak interval. The event indicator is 1 if a subsequent outbreak began within the study window, and 0 if the unit was censored (no reemergence observed by study end).

Inter-outbreak interval
\[ \Delta t_k = t^{\text{start}}_{k+1} - t^{\text{end}}_k \quad \text{(days between outbreak } k \text{ end and outbreak } k+1 \text{ start)} \] 
library(dplyr)
library(lubridate)

STUDY_END <- ymd("2022-12-31")

tte_data <- outbreaks |>
  # Work within each Admin-2 × disease stratum
  arrange(admin2_id, disease, start_date) |>
  group_by(admin2_id, disease) |>
  mutate(
    # End date of previous outbreak (lag by 1 row)
    prev_end   = lag(end_date),
    # Start of current outbreak = end of waiting time
    tte_stop   = start_date,
    # Waiting time origin = end of previous outbreak
    tte_start  = prev_end,
    # Event: 1 = reemergence occurred (non-NA prev_end means prior outbreak exists)
    event      = as.integer(!is.na(prev_end))
  ) |>
  # Drop first outbreak per unit (no prior outbreak = no interval to model)
  filter(!is.na(prev_end)) |>
  mutate(
    # Days at risk
    tte_days = as.integer(tte_stop - tte_start),
    # Right-censor units still at risk at study end
    event = if_else(tte_stop > STUDY_END, 0L, event),
    tte_stop = if_else(tte_stop > STUDY_END, STUDY_END, tte_stop),
    tte_days = as.integer(tte_stop - tte_start)
  ) |>
  filter(tte_days > 0) |>   # remove zero-length intervals (data artefacts)
  ungroup()

Left-Truncation and Right-Censoring Definitions

MechanismDefinition in This StudyHandled By
Left-truncationAdmin-2 unit had its first ever outbreak after study start — the unit was not under observation for reemergence before that eventCounting-process format (start, stop] naturally handles entry after t₀; first outbreak row dropped
Right-censoringAdmin-2 had no further outbreak by study end date (2022-12-31); exact reemergence time unknownevent = 0; tte_stop set to STUDY_END
Administrative censoringCountry withdrew from reporting (e.g., conflict zone); end of observation known but not end of riskFlag with cens_reason = "admin"; sensitivity analysis excludes these units
Competing eventsDisease officially eradicated from country before study endFlag cens_reason = "eradicated"; excluded from primary analysis, discussed as limitation
Frailty Term and Within-Unit Correlation Because the same Admin-2 unit contributes multiple intervals (if it had 3+ outbreaks), observations are not independent. The Cox frailty model addresses this with a unit-level random effect (frailty term) \(\theta_i \sim \text{Gamma}(1/\kappa, 1/\kappa)\), where \(\kappa\) is the variance parameter. In R: coxme(Surv(tte_days, event) ~ predictors + (1|admin2_id), data = tte_data).

Z-score Standardization
Scaling continuous predictors to unit-variance for model comparability and convergence
▼

Input

Raw continuous predictors on heterogeneous scales: NDVI (0–1), livestock count (0–10⁶), precipitation (mm/yr 0–4000), distance to market (km)

Output

Z-scored columns (suffix _z): mean = 0, SD = 1 across training set; scaler parameters (μ, σ) stored for test-set application

Why standardize?

Enables direct comparison of fixed-effect coefficients as "SD-unit change"; improves GLMM optimiser convergence; prevents numerical overflow in link function

The Formula

Z-score Standardization
\[z_i = \frac{x_i - \bar{x}}{s_x}\]

where \(\bar{x}\) is the training-set mean and \(s_x\) is the training-set standard deviation. After standardisation, a one-unit change in \(z_i\) corresponds to a one-SD change in the original predictor \(x_i\).

Why Standardize? — Three Arguments

  • Coefficient comparability: With predictors on the same scale, the magnitude of fixed-effect estimates directly reflects relative importance. A coefficient of 0.8 for NDVI_z and 0.2 for precipitation_z implies NDVI has 4× stronger association per SD shift.
  • Optimiser convergence: Mixed-effects models (fitted via BOBYQA, L-BFGS-B, or Nelder-Mead) converge faster and with fewer warnings when the design matrix is well-conditioned. Large-scale disparities inflate condition numbers and cause gradient instability.
  • Link-function stability: In logistic GLMM, extreme covariate values push fitted values to 0 or 1, saturating the logit link and producing near-infinite log-likelihood gradients. Standardisation keeps predictors in a numerically safe range.
# ---- Training / test split (e.g., 80/20 temporal split) ----
train_df <- outbreaks |> filter(outbreak_year <= 2018)
test_df  <- outbreaks |> filter(outbreak_year >  2018)

# Continuous predictors to standardise
cont_vars <- c("ndvi_mean", "livestock_sum", "precip_mean",
               "elevation_mean", "dist_market_km", "pop_sum")

# Compute scaler parameters from TRAINING SET ONLY
scaler_params <- train_df |>
  summarise(across(all_of(cont_vars),
                   list(mu = mean, sigma = sd),
                   .names = "{.col}__{.fn}",
                   na.rm = TRUE))

# Apply scaler to both sets (no leakage)
apply_zscore <- function(df, params, vars) {
  for (v in vars) {
    mu    <- params[[paste0(v, "__mu")]]
    sigma <- params[[paste0(v, "__sigma")]]
    df[[paste0(v, "_z")]] <- (df[[v]] - mu) / sigma
  }
  df
}

train_df <- apply_zscore(train_df, scaler_params, cont_vars)
test_df  <- apply_zscore(test_df,  scaler_params, cont_vars)

# Quick check: training set z-scores should have mean≈0, sd≈1
train_df |> summarise(across(ends_with("_z"), list(mean=mean, sd=sd), na.rm=TRUE))
Test-Set Leakage Prevention The scaler parameters \(\bar{x}\) and \(s_x\) must be computed exclusively on the training set and then applied to the test/validation set. Fitting the scaler on the full dataset contaminates the test set with information from the future, inflating apparent predictive performance. Store scaler_params as a named list and save to disk for reproducibility.

Zero-Variance and Near-Zero-Variance Checks

# Detect constant or near-constant columns (sigma ≈ 0)
low_var <- scaler_params |>
  pivot_longer(everything(), names_to = "param") |>
  filter(grepl("__sigma", param), value < 1e-6)

if (nrow(low_var) > 0) {
  warning("Near-zero variance detected: ", paste(low_var$param, collapse=", "))

}

Missing Data Assessment
MCAR/MAR/MNAR taxonomy, naniar visualisation, and mice multiple imputation
▼

Input

Merged analysis dataset with potential missingness in vaccination coverage, wildlife classification, remote-sensing derived predictors, and administrative data

Output

Missingness report; imputed complete-case dataset (for MAR variables); exclusion log for MNAR variables; aggr() and gg_miss_var() plots

Why classify mechanism?

Imputation is only valid under MAR (or MCAR). MNAR requires structural corrections or sensitivity analyses; misclassification leads to biased estimates

Decision Rule: When to Use Complete-Case Analysis

Complete-Case Threshold: < 5% Missing If a variable has fewer than 5% missing values AND Little's test does not reject MCAR, listwise deletion is acceptable — the loss in statistical power is minimal (<0.5% efficiency loss for typical sample sizes >500) and the analysis is simpler to audit. Document this decision explicitly in the methods section.
Imputation Exclusions Never impute the outcome variable (persist, event, tte_days). Rows with missing outcomes must be excluded and logged. Imputing outcomes biases the event rate and frailty variance estimates.

Final Dataset Assembly
One-row-per-outbreak-unit format, duplicate checks, variable manifest, and summary statistics
▼

Input

Spatially-joined predictor table; binary persistence outcome; TTE dataset; imputed/complete predictor columns; factor-encoded categorical variables

Output

Two model-ready datasets: glmm_df (one row per outbreak × Admin-2, binary outcome) and cox_df (one row per inter-outbreak interval, TTE outcome)

Why separate tables?

GLMM and Cox frailty have different unit-of-analysis requirements; sharing a single table would require awkward pivoting and increases error risk during model specification

Final Join and Deduplication

Long-Format Principle Both glmm_df and cox_df follow a strict one-row-per-observational-unit structure. For the GLMM, each row is one outbreak event at one Admin-2 district. For the Cox model, each row is one inter-outbreak interval. This "long format" is the correct input for lme4::glmer() and coxme::coxme() respectively, and prevents the silent row-duplication bugs that arise when pivoting wide tables.
